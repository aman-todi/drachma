# Use Supabase Postgres, not AWS RDS, despite hosting the app on AWS

The application (FastAPI backend, React SPA) is hosted on AWS, and Postgres could naturally have lived there too as RDS or Aurora. We're using Supabase Postgres instead, paired with Supabase Auth, because the Custom query tool's security model depends on row-level security tied directly to `auth.uid()` — RLS-as-policy is a first-class Supabase feature, whereas on RDS we'd hand-roll the RLS-Auth integration ourselves. The trade-off we accepted: Supabase's read replicas are a higher-tier-plan feature, so the Custom query tool runs against primary for v1, leaning on its other guardrails (read-only role, LIMIT injection, timeout) instead of replica isolation. We'll add a replica later if query volume or latency makes it necessary.
